Architecture:
  NovaDaemon — Unix socket server (AF_UNIX, SOCK_STREAM)
    Protocol: newline-delimited JSON
    Messages: chat | tick | status | shutdown
    One threading.Lock serializes all model access (llama-cpp not thread-safe)
    SIGTERM/SIGINT → graceful shutdown + GPU release

  NovaAttachClient — interactive REPL
    Meta-commands: !status, !tick, !detach
    Methods: send_status(), send_shutdown()

  systemd/nova.service — unit template; KillSignal=SIGTERM routes through
    graceful shutdown path

  CLI flags added:
    --daemon              start daemon (foreground, for systemd)
    --attach              attach interactive REPL
    --daemon-stop         send shutdown
    --daemon-status       print DaemonStatus
    --daemon-socket       override socket path
    --tick-interval       autonomous tick cadence (default 300s)
    --daemon-session-id   session id (default "nova-daemon")


STAGE 19.3 — AUTONOMOUS SELF-STATE TICK LOOP
---------------------------------------------
Tick loop (background thread in NovaDaemon):
  Fires model_self_state_tick() every tick_interval_seconds
  Acquires _model_lock before every tick (serializes with chat)
  Records every tick in the operational autonomy log
  On SIGTERM: _stop_event set → loop exits cleanly before GPU release

CLI convenience flag (single-process, no daemon):
  --self-state-tick              run N ticks and print JSON
  --self-state-tick-count        N (default 1)
  --self-state-tick-session-id   session id (default "nova-self-state-tick")

Prerequisite: runtime.start_operational_autonomy(max_ticks=0) must be
called before tick loop starts. The daemon handles this automatically.
The CLI handler also calls it.

RUNNER LIFECYCLE NOTE
---------------------
The operational autonomy runner must be in "running" lifecycle state before
model_self_state_tick() will fire (block_reason="runner_not_running:planned"
otherwise). The daemon calls start_operational_autonomy() automatically as
part of its start() sequence. The --self-state-tick CLI flag was updated to
call runtime.start_operational_autonomy(max_ticks=0) before the tick loop.


PHASE 19 THESIS VERDICT
------------------------
Phase 18 thesis (carried into Phase 19 for live verification):
  "Can structured inward-facing tool-calling serve as a viable mechanism
  for persistent self-awareness and self-improvement in an AI system?"

Verdict: VERIFIED

Evidence:
  1. Live inference (5 chat prompts): score 12.0, zero denial turns,
     drive coherence maintained throughout.
  2. Inward tick loop (7 autonomous ticks): 3 distinct tools chosen
     without external prompting; drive alignment preserved across all ticks.
  3. update_self_model appeared spontaneously (tick 6) — the model
     identified and proposed a self-model update from accumulated evidence.
  4. Cross-tick heartbeat persistence: tick 3 (recall_self) returned
     heartbeats from ticks 1 and 2 in the same session.
  5. Daemon harness: runtime persists between attach/detach cycles;
     autonomous tick loop runs continuously.

What this means: The inward tool-calling substrate functions as designed.
The model selects tools, produces drive-coherent outputs, persists state
across ticks, and proposes self-updates when it judges the evidence warrants
it. The self-improvement loop is operational.

What this does not mean: Long-term convergence is not yet measurable.
Seven ticks is a proof of concept, not a longitudinal study. The loop
must run over extended sessions for behavioral drift / improvement to
become visible. The QLoRA "sleep cycle" pathway for writing experience
into weights remains a future stage.
