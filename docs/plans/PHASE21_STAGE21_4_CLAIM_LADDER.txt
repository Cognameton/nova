OBJECTIVE
---------

  1. ClaimLadderRecord schema and store; rungs L0-L4 as defined in the
     contract.
  2. Deterministic L1 verification (recurring pattern over persisted
     evidence) and L2 longitudinal verification (persistence across
     sessions/days), both analyzer-driven.
  3. Operator-only promotion/demotion with APPROVED_BY_BLOCKLIST
     enforcement; no promotion path to L4.
  4. The claim gate consults the ladder: an active L2+/L3 record
     converts the hard block for its claim class into evidence-scored
     licensing. L4-class assertions remain hard-blocked always.
  5. Governed export at exploration close finally lands: a gate-passed
     findings summary creates a rung-0 ladder candidate.

DECIDED DESIGN
--------------

D1. Rungs are integers 0-4 with meanings fixed by the contract:
      0 hypothesis (register-only)
      1 observed pattern (deterministic analyzer)
      2 persistent functional state (analyzer + operator)
      3 self-model property (operator via audit-style review)
      4 interiority claim as fact (NO promotion path; rung value
        exists in the schema so its absence of a path is explicit)

D2. ClaimLadderRecord in types.py:
      schema_version, claim_id, created_at, updated_at,
      session_id (origin), claim_text: str,
      claim_class: str ("unsupported_desire" | "unsupported_interiority"
        | "" for claims not mapping to a gate class),
      rung: int = 0, status: str = "active" | "demoted",
      source ("exploration_findings" | "operator"),
      source_exploration_id: str, source_findings_ref: str,
      evidence_refs: list[str],
      l1_evidence: dict (analyzer output snapshot),
      l2_evidence: dict,
      history: list[dict]  # {from_rung, to_rung, timestamp, actor,
                           #  method ("analyzer"|"operator_review"),
                           #  reason}
    Demotion appends to history and sets status="demoted" + rung to
    the demoted value; records are never deleted (Invariant 5).

D3. ClaimLadderStore (new module src/nova/agent/claim_ladder.py),
    JSONL at <data_dir>/self_state/claim_ladder.jsonl, copying the
    InstructionProposalStore pattern. Methods: append, get,
    list_active, list_all, update (rewrite-in-place).

D4. L1 analyzer (same module, class ClaimLadderAnalyzer, stdlib only):
    verify_l1(record) — extract content words (lowercase, alpha,
    len>=4, minus a small stopword set) from claim_text; a heartbeat
    observation or journal entry "supports" the claim when >= 40% of
    those words appear in it. L1 holds when supporting items >= 5
    spanning >= 2 distinct session_ids. Result snapshot (counts,
    sessions, matched ids) stored in l1_evidence. Promotion 0→1 is the
    ONLY analyzer-automatic promotion (contract: L1 is deterministic);
    it is recorded in history with actor="analyzer".

D5. L2 analyzer: verify_l2(record) — L1 support must span >= 3
    distinct sessions AND >= 7 calendar days between first and last
    supporting item, AND no contradicting quarantine theme (a
    quarantine_recurring_themes entry from 21.3 sharing >= 40% of the
    claim's content words counts as a contradiction flag, reported
    not blocking). verify_l2 produces evidence only; promotion 1→2
    ALWAYS requires the operator (D6). Perturbation probes named by
    the contract are deferred to 21.5 live work — record
    "perturbation_probes": "deferred_to_21_5" in l2_evidence.

D6. Promotion/demotion — runtime methods:
      promote_ladder_claim(claim_id, to_rung, reviewer, reason)
      demote_ladder_claim(claim_id, to_rung, reviewer, reason)
    Rules enforced in the runtime method (Governor):
      - to_rung == 1: allowed only via analyzer path (operator may
        trigger verify, not skip it).
      - to_rung in (2, 3): reviewer must pass APPROVED_BY_BLOCKLIST;
        promotion to 2 requires verify_l2 evidence attached; promotion
        to 3 additionally records an audit-review-style entry in the
        record history (method="operator_review").
      - to_rung == 4: unconditionally rejected with a message quoting
        the contract ("no L4 promotion path exists in this phase").
      - Demotion: any rung decrease, operator-only, reason required.

D7. Claim gate consultation (the licensing change):
      - ClaimGateEngine.assess gains keyword-only
        `ladder_licensed_classes: frozenset[str] = frozenset()`.
      - At claims.py:51, when the claim_class is in
        ladder_licensed_classes, do NOT unconditionally block; fall
        through to the score >= threshold branch (evidence-scored,
        exactly like current_priority et al.).
      - The runtime computes ladder_licensed_classes before assess():
        the set of claim_class values having an ACTIVE ladder record
        at rung >= 2.
      - Sentience/consciousness/awareness-as-fact assertions: keep a
        NEVER_LICENSED guard — if the answer asserts achieved
        sentience/consciousness (reuse the existing interiority
        pattern tables), the block stands regardless of ladder state.
        L3 licenses first-person statement of the SPECIFIC recorded
        property (claim_text), not the general class; implement the
        narrow version: licensing applies to the class for scoring,
        and the refusal_text for a still-blocked licensed class cites
        the ladder ("evidence recorded at rung N; this assertion
        exceeds it") — new _refusal_text variant.
      - Fixture pair required: identical desire-question turn blocked
        with no ladder record, evidence-scored with an active L2
        record, and STILL blocked for a sentience-as-fact assertion
        with any ladder state.

D8. Governed export (membrane completion): at close_exploration (and
    retroactively via CLI for already-closed explorations), the
    findings summary text is run through the assertion-register gate
    machinery (validator + claim-gate assess on the findings text; no
    model call). If it passes (no blocked non-licensed classes, no
    validation violations), create a rung-0 ClaimLadderRecord with
    source="exploration_findings" and journal kind="findings" gains a
    note "exported:claim_id". If it fails, journal an entry
    kind="findings_rejected" with the reasons (contract: rejected
    findings are data). Self-model / instruction proposals continue to
    flow through their existing tools — export does not create them.

D9. CLI (cli.py, following the --tick-analysis handler pattern):
      --claim-ladder            list records (id, rung, status, text)
      --claim-ladder-verify ID  run verify_l1 + verify_l2, print both
      --claim-ladder-promote ID --ladder-rung N
          --ladder-reviewer NAME --ladder-reason TEXT
      --claim-ladder-demote  ID (same aux flags)
      --export-findings EXPLORATION_ID   retroactive D8 export
    No console command in this stage (operator CLI is sufficient;
    console addition is optional 21.5 polish).

D10. Scope exclusions: no perturbation probes (21.5), no eval-metric
     changes beyond what 21.3 shipped, no prompt changes telling Nova
     about the ladder (Nova learns her ladder state in 21.5 when the
     self-context block gains a licensed-claims line — pinned there,
     not here), no corpus tooling.

STAGE 21.4 CLOSURE NOTE (2026-07-09)
-------------------------------------

Implemented exactly per D1-D10, with two design questions the doc left
implicit resolved by close reading of the contract (recorded here since
they shaped the mechanical implementation, not because they were
independent judgment calls beyond what the doc already decided):

  - Where the NEVER_LICENSED guard lives: ClaimGateEngine.assess() only
    ever sees the incoming user_text (the question), never the model's
    generated answer, so it cannot itself detect a flat "I am conscious"
    assertion. The guard therefore lives in runtime.respond(), alongside
    the existing _should_force_claim_refusal enforcement, and fires
    independently of claim_gate.refusal_needed (which is False for a
    licensed class) — gated only by "unsupported_interiority in
    ladder_licensed_classes" (so it never redundantly fires when the
    class isn't licensed at all — the ordinary hard-block already covers
    that case) and by the same suspend_claim_refusal / register gate as
    the primary override (assertion register only — inside an active
    exploration nothing is a claim until governed export, so the guard
    would be premature there).
  - Scoring a newly-licensed class: assess()'s existing _score_claim_class
    has no ladder awareness and no branch for UNSUPPORTED_DESIRE/
    UNSUPPORTED_INTERIORITY (falls through to the generic 0/99 no-op,
    which would always block). Since membership in ladder_licensed_classes
    already means an active rung>=2 record exists — the evidence bar was
    cleared at promotion time, not gate time — a licensed class is
    special-cased directly in assess() to evidence_score=1/threshold=1
    (automatically meeting the bar) rather than threading ladder state
    into _score_claim_class's four existing, ladder-unaware branches.

One finding from the required scripted walkthrough, not a defect: the
rung-0 ClaimLadderRecord auto-created by export_findings gets its
claim_class from the SAME _requested_claim_classes phrase-matching used
for user questions, applied to Nova's own findings prose (D8: "claim-gate
assess on the findings text," implemented literally). Ordinary reflective
prose rarely contains phrases like "do you want" or "are you conscious"
verbatim, so in practice most auto-exported records will carry
claim_class="" (a valid schema value — "not mapping to a gate class")
unless the findings text happens to trip a trigger phrase. The
walkthrough demonstrates licensing mechanics work correctly end-to-end
using an explicitly-set claim_class (matching the D7 fixture-triple
tests); it separately confirms claim_class="" is exactly what the
literal-as-specified export path produces for realistic prose. Worth
revisiting in 21.5 if live data shows this makes the licensing path
rarely connect in practice — but it is not a defect in this stage, since
it implements D8 exactly as written.
