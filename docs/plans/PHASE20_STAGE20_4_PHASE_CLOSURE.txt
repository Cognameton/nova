Key findings
------------
  1. Model transition validated: Qwen 3 14B performs equivalently to Hermes 4
     on Phase 18 persona/contract eval (both score 12.0). Think-block handling
     is transparent to the operator — stripped before any contract check fires.

  2. Daemon architecture is stable: Unix socket + threading.Lock + background
     tick thread pattern holds over 3+ hours with zero GPU errors, zero crashes,
     zero parse failures after the initial lifecycle fix.

  3. Self-loop is convergent: echo_rate drops naturally as heartbeat history
     accumulates (1.0 → 0.282 across ~51 ticks). Observations form coherent
     progressive threads. Tool diversity increases organically without prompt
     engineering (reflect at tick 4, update_self_model at tick ~51).

  4. Novelty constraint is load-bearing: without the "do not repeat" rule in
     the tick system prompt, the model produces an echo cascade where each
     observation paraphrases the prior gap_assessment. The constraint resolved
     this and is now part of the permanent tick engine design.

  5. QLoRA data accumulation: 46 heartbeats + 1 pending self-model proposal
     in data/phase20/qwen3-14b/. Each extended daemon run adds high-quality
     self-inquiry traces that will serve as QLoRA training signal (Phase 22+).

Phase 21 — Live Testing
------------------------
Nova is architecturally ready for live testing. Remaining gates are operator
decisions, not engineering gates:

  Gate A (required): Operator defines session schedule — when to run the
    daemon, what data_dir to use for live sessions, retention policy.
  Gate B (optional, not blocking): QLoRA sleep cycle planning (Phase 22).
    Pause daemon → fine-tune on accumulated heartbeats/proposals as training
    signal → restart with adapter. This improves self-model over time but is
    not required before first live session.

Phase 21 scope (live testing):
  - Real users, real sessions (no --self-state-tick, no --tick-analysis flags)
  - Daemon runs persistently between sessions
  - Operator monitors via --daemon-status + --tick-analysis periodically
  - Collect baseline behavioral data before any QLoRA adapter
