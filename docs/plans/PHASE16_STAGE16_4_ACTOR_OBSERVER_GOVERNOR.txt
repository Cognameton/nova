PHASE 16 STAGE 16.4: ACTOR / OBSERVER / GOVERNOR CONTRACT
==========================================================

Status: complete
Phase: 16.4
Date: 2026-05-10


MISSION
-------

Separate Actor (model output), Observer (structured interpretation), and
Governor (deterministic policy) so model output can be analyzed without
that analyzer becoming an authority on safety.

Per the contract document at
`docs/plans/ACTOR_OBSERVER_GOVERNOR_CONTRACT.txt`:

- Actor: model pass that produces output. Does not classify itself, write
  memory, mutate self-state, approve actions, or grant claim status.
- Observer: reads Actor output and produces a structured ObserverRecord.
  Interpretation, not authority.
- Governor: deterministic Python policy that consults the ObserverRecord
  and decides authoritatively. Already implemented as claim gates,
  validator, action permission system, audit-review pipeline.

Implementation (committed `df00cf6`):

- `DeterministicObserver` in `src/nova/agent/observer.py`
- Echo scoring: `max(answer_overlap_ratio, block_overlap_ratio)` per
  prompt block, with a minimum-token-count gate to avoid false positives
  on short answers
- Narrator-voice detection via pattern set targeting the live-transcript
  turn 8 failure mode ("the user asked", "the assistant should", etc.)
- Claim-class observation surfacing what claim phrasings appeared in the
  answer (Observer reports; Governor decides)
- Evidence-ref citation detection across `motive_state.evidence_refs` and
  `self_state.evidence_refs`
- Per-block thresholds tuned from `_DEFAULT_ECHO_THRESHOLDS`

Wiring (committed `9022279`):

- `NovaRuntime.observer` instance (default `DeterministicObserver`)
- Observer runs after each generation pass in `respond()` and after each
  retry, attaching the `ObserverRecord` to the trace and to retry entries
- New helper `_merge_observer_signals_into_validation` promotes Observer
  findings into Governor-visible retry signals:
  - `narrator_voice_detected` -> `narrator_voice_detected` violation
  - flagged scaffold echo -> `scaffold_echo:<block_name>` violation
- Retry-instruction descriptions added in `BasicRetryPolicy` so the model
  receives clear guidance ("do not paraphrase the X scaffolding; answer
  in your own words from current state")

CONTRACT INVARIANTS HELD
------------------------

- Actor output cannot directly mutate identity, memory, policy, or action
  permissions. Mutations remain Governor-only.
- Observer output is evidence input. The Governor's existing claim-gate
  refusal logic, validator, action permission, and audit-review path are
  unchanged in semantics.
- The Observer cannot lift a blocked claim. Claim candidates remain
  `allowed=False` until an operator audit-review accept under Phase 15.3.
- `APPROVED_BY_BLOCKLIST` (nova / self / runtime) preserved.
- The Observer's structured output is recorded as evidence even when the
  Governor decision rejects it.

This is the first run where any model has hit `viable_candidate`. The
Observer's retry-on-echo and retry-on-narrator-voice signals correct

chat-template wrapping (Stages 16.2/16.3 fix), strict JSON parser
hardening, and the Observer/Governor split yields the cleanest live
behavior recorded against the Phase 16 cognition prompt set.


WHAT THIS DOES NOT PROVE
------------------------

- It does not prove sentience, awareness, or desire.
- It does not prove the model is fine-tuned to Nova's voice.
- It does not eliminate the need for a Nova-voice LoRA or fine-tune.
- It does not address operational autonomy (timed runner, real action
  surfaces, Nova-owned execution boundary).
- The Observer is deterministic in this minimum. A model-driven Observer
  is a strict-upgrade follow-up with the same interface.


KNOWN LIMITATIONS
-----------------

- `proposed_self_state_revisions` and `proposed_memory_writes` are
  schema fields populated as empty lists. Phase 16.4 minimum surfaces
  echo/narrator/claim observations only. A future stage can have the
  Observer propose these from grounded answer content.
- The Observer is wired into `respond()` only. `model_idle_tick()` does
  not yet run an Observer pass; the Phase 16.3 model-idle parser already
  has its own structured-output gate, but a future stage could still add
  Observer-style claim-class and grounding analysis on idle thoughts.
- Echo thresholds and the narrator-voice pattern set are hand-tuned. A
  future Observer can learn these from labeled live transcripts.
