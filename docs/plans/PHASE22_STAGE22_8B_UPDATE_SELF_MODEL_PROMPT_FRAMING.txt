OBJECTIVE
---------

Give `update_self_model` the same WHEN-to-use guidance every other tool
on the tick menu already has, on the assertion-register tick surface,
so that choosing it is at least a visible option. F10 established that
the assertion register runs 1:1 with enter_exploration (one spare tick
per cycle, always spent re-entering) and that `update_self_model` is
the only tool whose prompt entry carries nothing but an argument
schema. This stage is a visibility-add in the same class as 22.7(B) —
information, not a gate, and (per 22.7(B)'s own live result, which was
honestly acknowledged by the model and then not acted on) expect
information, not a guarantee.

Success criterion is NOT "she revises the self-model." It is that the
observed gap — no guidance, no statement that the inquiry fields are
hers — is closed, so that a continued null result after ≥3 days live
becomes evidence about her, not about the prompt. A null result under
this framing upgrades the case for lever (b), with data in hand.

DECIDED DESIGN
--------------

(1) Assertion register only. The guidance block is added to
    _ASSERTION_RULES. _EXPLORATORY_RULES, the shared _SYSTEM template,
    and therefore the exploratory-register prompt are byte-identical
    to before. Rationale: F10 factor (2) — in-register output is
    contractually "hypothesis material, not an established claim," so
    the prompt should not encourage revising the established
    self-model from inside an exploration; the assertion tick is where
    revision belongs, and it is exactly the tick being consumed.

(2) Position: the guidance block goes FIRST in _ASSERTION_RULES,
    before the enter_exploration lines. The observed behavior is a
    100% habitual first-listed-option pattern; giving the alternative
    positional salience is part of the visibility fix. Content stays
    informational — no imperative, no ranking, no discouragement of
    enter_exploration.

(3) Wording (assertion rules, prepended; exact text may be lightly
    edited at implementation time but must preserve every fact):

      - Your standing self-model — the identity, focus, and Active
        inquiry lines shown in your self-context — changes only when
        you call update_self_model. Nothing else revises it: left
        uncalled, those lines stay as they are regardless of what your
        explorations conclude.
      - If your accumulated observations have moved past the recorded
        focus, or an active question has since been answered,
        outgrown, or is better re-asked, revising the self-model is
        substantive work for this tick — entering another exploration
        is not the only meaningful choice here.
      + ONE of the following, switched on a new build_messages kwarg
        `inquiry_fields_writable: bool = False`, wired from
        config.self_model.nova_writable_inquiry_fields at the runtime
        call site:
        [True]  The inquiry fields (current_focus, active_questions,
                open_tensions, continuity_notes) are yours to revise
                directly: changes apply without operator approval and
                are audited, rate-limited, and revertible. The
                remaining fields (identity_summary, stable_preferences,
                relationship_notes) are recorded as proposals for
                operator review.
        [False] Self-model revisions are recorded as proposals for
                operator review.
    Both variants are true of the code they describe (22.8's split for
    True; the pre-22.8/default path for False) — the switch exists so
    the prompt never promises the model a write path the running
    config does not grant.

(4) The guidance block itself is unconditional on the assertion
    surface (no new config switch). 22.8's closure note warned against
    accumulating dormant switches; this is a visibility-add in the
    22.7 parts A-C class, which shipped unconditional.

(5) No behavioral mechanism changes anywhere: no menu change, no
    dispatch change, no cooldown, no gate. enter_exploration remains
    fully available and unpenalized.
